# ADR-003: Chunk 策略优化（500/200 + tail-char overlap）

- 状态: 已接受
- 日期: 2026-08-21（自根目录 `RAG_检索优化指南.md` 迁移）
- 相关: FEAT-004（文档详情与分块）

## 背景

原 chunk 配置 `max_chunk_size=1000` 过大、可能混杂多个语义单元；无 overlap，跨块边界信息丢失。

## 决策

- `max_chunk_size`: 1000 → **500**
- `min_chunk_size`: 100 → **200**
- 新增 **tail-char overlap**：相邻分块之间用前块尾部字符衔接，避免跨块事实割裂

## 后果

- 正面: 检索精度提升（chunk 语义更纯粹）；边界信息保留；长文档理解增强
- 负面: chunk 数量增加、存储与 embedding 成本略升
- 取舍: 未采用 embedding 相似度驱动的语义分割（依赖批量 embedding，成本高），先用固定大小 + overlap

## 落地

- `backend/app/services/chunker.py` — `MarkdownChunker(max_chunk_size=500, min_chunk_size=200, overlap=0)`；overlap 通过 tail-char 前缀实现（默认 0，调用方可传参）
