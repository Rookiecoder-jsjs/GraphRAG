# ADR-006: 图谱引导检索（Graph-Guided Retrieval）

- 状态: 已接受
- 日期: 2026-08-21（自根目录 `RAG_检索优化指南.md` 迁移）
- 相关: FEAT-007（知识图谱）、FEAT-010（AI 对话）

## 背景

图谱原本仅做后置实体补充，未深度参与召回；多跳推理能力弱。

## 决策

采用图谱引导检索：**query → 实体提取 → Neo4j 遍历 → 构建硬候选集 → 与混合/向量检索结果互补**。

- 从 query 提取实体，经 Neo4j 找到 MENTION 这些实体的 chunks 作为硬候选集
- 无实体提取到或图谱无命中时**静默回退**到纯混合/向量检索，不阻塞
- 检索结果同时把**关系三元组**送入 LLM 上下文，来源可归因

## 后果

- 正面: 多跳推理能力显著提升；图谱价值深度挖掘；隐含关联发现；答案可归因
- 负面: 增加一次实体提取 + Neo4j 遍历（延迟 +100ms 左右）；依赖实体抽取质量
- 取舍: 图谱结果作为候选集与向量结果互补而非替代；引入可控关系类型与注入防护，避免脏数据进上下文

## 落地

- `backend/app/services/retriever.py` — `use_graph_rag=True` 时启用（`build_rag_context` 传入）
- `backend/app/services/neo4j_client.py` — 实体/关系遍历
- `backend/app/api/chat.py` — `build_rag_context(use_graph_rag=...)`
