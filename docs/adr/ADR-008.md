# ADR-008: 文档转换器选型 markitdown → anydoc

- 状态: 已接受
- 日期: 2026-09-10
- 相关: ADR-007（摄取链路）、ADR-003（切块策略，转换是链路第一环）

## 背景

上传链路用 markitdown 0.0.1a3（2024 alpha）做文档→Markdown 转换。实测（anydoc 官方
fixtures 11 个 docx + 对抗样本 + 自造损坏文件）暴露三个现网问题：

1. **docx 静默产出垃圾**：11 个样本中 4 个（36%）不走解析器，直接把 zip 内原始
   OOXML（`<w:p>` 等标签）当 Markdown 倾倒（输出 43K 字符全是 XML）。垃圾直接流入
   切块→embedding→LLM 抽取，污染图谱。
2. **异常继承 BaseException**：`UnsupportedFormatException` /
   `FileConversionException` 不继承 `Exception`，`md_parser` 与上传接口的两处
   `except Exception` 全部接不住——一个"前 1KB 含 %PDF 的损坏文件"（能通过魔数守卫）
   直达未处理 500，且上传接口的 `os.remove` 清理不执行、文件永久残留。
3. **zip bomb 挂死线程**：转换无资源上限，196KB 的 zip bomb 令 markitdown >25s 无响应
   （转换跑在 `asyncio.to_thread`，永久占用线程池 worker；DOC_INGEST_CONCURRENCY 闸
   限并发数，挡不住 per-task 卡死）。MAX_FILE_SIZE 检查压缩后体积，拦不住。

另：markitdown 运行时传递依赖 51 包（pandas/openai/pillow/lxml/mammoth…），项目仅用
其 6 种格式中的 4 种；csv/xls/rtf 直接抛不支持。

## 决策

文档转换器换成 **firecrawl-anydoc 0.2.4**（Rust 实现、PyPI 零传递依赖、abi3 wheel 覆盖
win/linux/mac、MIT）。`utils/md_parser.convert_document_to_markdown` 内部替换实现，
**对外契约不变**：失败一律降级为空串/回退（上传接口回 400），扫描版 PDF 走显式
`NeedsOcrError` 分支同样返回空串。`ALLOWED_EXTENSIONS` 扩容不在本 ADR 范围。

## 后果

- 正面:
  - 上述三个现网问题随换库消失（错误全部继承 `Exception`；内置 max_xml_depth /
    max_entry_bytes 资源上限，对抗样本 140–190ms 内显式报错）；
  - 格式能力 6→14 种（pptx/xls/odt/rtf/epub/csv 备用），转换中位耗时约 30–100 倍下降
    （实测 docx 257ms→2ms、xlsx 692ms→1.1ms），摄取闸内占用大幅缩短；
  - 依赖闭包 51 包→0 包，venv 显著瘦身。
- 负面:
  - 项目年轻（2026-08 创建，4 位贡献者），存在维护风险；预编译 wheel 绑平台/Python
    下限 3.10；
  - 扫描版 PDF 不支持 OCR（从"静默空串"变为"显式 NeedsOcrError→空串"，行为等价但可
    区分；要 OCR 需另接服务）；
  - markitdown 的 `.title` 元数据来源消失，标题一律从 H1 提取（原本也几乎取不到），
    无 H1 时回落文件名。
- 取舍:
  - 不升级 markitdown 至 0.1.x：仍是 Python 全量依赖、无资源上限，②③不解决；
  - 不自研转换器：格式解析（尤其 .doc/.xls 旧格式）成本远超引入一个零依赖库；
  - anydoc 官方 benchmark 数字有自利嫌疑，但本决策依据的是本地独立复测
    （`tests/test_md_parser.py` 固化了回归契约），不依赖其自报分数。

## 落地

- `requirements.txt` — `markitdown==0.0.1a3` → `firecrawl-anydoc==0.2.4`
- `backend/app/utils/md_parser.py` — 换 anydoc 实现；`NeedsOcrError` 显式分支；
  失败降级契约不变
- `backend/tests/test_md_parser.py`（新增，13 用例）— docx 非 OOXML 倾倒、错误可捕获
  降级、深嵌套炸弹快速失败、扫描 PDF 空串（fixture 来自 anydoc MIT 测试套件）
- `README.md` — 目录树注释 / 上传流程图 / 依赖清单 / 注意事项第 7 条
- 全量回归 350 绿（337 存量 + 13 新增），markitdown 已从环境卸载验证零残留引用
