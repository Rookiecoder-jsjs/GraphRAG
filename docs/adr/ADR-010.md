# ADR-010: 全局问答——社区成员 chunk 通道而非摘要上 prompt

- 状态: 已接受
- 日期: 2026-09-11
- 相关: FEAT-028、ADR-006（图谱引导检索）、ADR-009（查询闸）

## 背景

知识图谱建好后只能答"某个实体/关系"的局部问题（ADR-006 图通道），答不了
"这批文档整体讲什么"的全局问题。GraphRAG 的标准做法是社区摘要直接进
生成 prompt（global search）；同时 FEAT-028 引入了每社区一次 LLM 调用的
重建任务，需要决定它与 ADR-009 查询闸的关系。

## 决策

1. **社区摘要只做"选块依据"，不上生成 prompt**——全局通道回注的是社区
   成员实体的 chunk（走既有 RRF→重排→引用管线）；`rag_system.md` 零改动。
2. 社区检测用 **networkx greedy_modularity_communities**（确定性、纯
   Python、无新原生依赖），不手写标签传播。
3. **rebuild 不占查询闸**——闸是检索准入队列（QUERY_CONCURRENCY=4），
   分钟级 LLM 任务占槽会饿死 chat/search；用专用 `communities_limiter`
   5/300s + 构建内 Semaphore(8) 替代。
4. chroma 社区向量**先 delete 后 upsert**（位置 id 缩容安全）；SQLite 行
   在向量落库后替换。

## 后果

- 正面: 生成 prompt 与引用管线零改动 → eval 生成指标无被扰动面（军规②
  对比噪声带内）；回答仍可逐条引用真实 chunk；确定性分组让重建可测可复现。
- 负面: 全局问题的答案由成员 chunk 拼出，不如"直接读摘要"省 token；
  chunk 检索未覆盖的社区语义不会出现在答案里（页面直接展示摘要补足）。
- 取舍: 放弃 GraphRAG 式"摘要直入 prompt"——它要改 rag_system.md、引入
  不可引用的合成上下文，且直接触碰军规②守护的生成质量面；成员 chunk 方案
  以极小的 token 代价换取完全的引用可溯源与生成路径零风险。
